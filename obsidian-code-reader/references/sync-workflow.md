# 仓库同步工作流

当代码仓库有变更时，增量更新已有的解读笔记。

## 步骤 1: 确认目标仓库

同「仓库解读」的仓库确认逻辑，但要求仓库已有解读记录。

## 步骤 2: 读取仓库元数据

读取 `<vault>/代码解读/<仓库名>/_repo_meta.md`，获取：
- `上次解读commit`
- `文件-笔记映射`

如果 `_repo_meta.md` 不存在，提示用户需要先执行「仓库解读」。

## 步骤 3: 检测变更

```bash
# 切换到仓库目录
cd <仓库路径>

# 获取当前最新 commit
git rev-parse HEAD

# 如果与上次解读 commit 相同 → 无变更，结束
# 如果不同 → 获取变更文件列表
git diff --name-status <上次解读commit>..HEAD
```

`git diff --name-status` 输出格式：
```
M   src/auth/jwt.py          ← 修改
A   src/new_module/init.py   ← 新增
D   src/old_module/legacy.py ← 删除
R   src/utils.py → src/helpers.py  ← 重命名
```

## 步骤 4: 分析影响范围

将变更文件与 `_repo_meta.md` 中的映射表比对：

**4.1 修改的文件（M）：**
- 在映射表中找到对应笔记
- 重新读取该文件的新版本
- 更新笔记中的相关描述和代码片段

**4.2 新增的文件（A）：**
- 判断新文件属于已有模块还是全新模块
- 已有模块 → 在对应笔记中补充新文件的解读
- 全新模块 → 创建新的解读笔记

**4.3 删除的文件（D）：**
- 在映射表中找到对应笔记
- 从笔记中移除已删除文件的相关内容
- 如果整篇笔记的所有源文件都已删除 → 标记笔记为废弃或删除

**4.4 重命名的文件（R）：**
- 更新映射表中的路径
- 更新笔记中的源码路径引用

## 步骤 5: 执行更新

向用户展示影响分析：
```
仓库: repo-name
变更范围: abc1234..def5678 (15 commits)
检测到 8 个文件变更：

需要更新的笔记：
  - 认证模块-JWT鉴权 (src/auth/jwt.py 被修改)
  - REST-API-概览 (新增了 3 个 API 路由)

需要新建的笔记：
  - 通知模块-邮件发送 (新增 src/notification/)

需要清理的内容：
  - 用户管理-CRUD 中移除旧版 legacy 接口描述

确认执行？
```

用户确认后，逐个执行更新。更新笔记时：
- 保留笔记原有的结构和未受影响的内容
- 只修改与变更文件相关的部分
- 更新代码片段为新版本
- 在笔记末尾的 frontmatter 旁添加更新记录

## 步骤 6: 更新元数据

更新 `_repo_meta.md`：
- `上次解读commit` → 当前 HEAD
- `上次解读时间` → 当前时间
- 更新文件-笔记映射表

## 步骤 7: 维护索引

更新受影响笔记所在目录的 `_index.md`（笔记摘要可能变更），以及上级目录的笔记数。

## 步骤 8: Git 自动同步

读取 `references/git-sync.md` 执行 vault 的 Git 同步。
