## 项目概览

**目标**：让读者 5 分钟内理解这个项目是什么、用了什么技术、怎么组织的。

**分析方法**：
1. 读取 README.md，提取项目定位和功能描述
2. 读取包管理文件（package.json / pyproject.toml / pom.xml 等），提取：
   - 项目名称、版本
   - 核心依赖及其版本
   - 构建/启动命令
3. 分析目录结构，画出一级/二级目录树并标注每个目录的职责
4. 读取 Dockerfile / docker-compose.yml，了解部署方式

**产出笔记**：`项目概览.md`

**必须包含**：
- 项目定位（一句话）
- 技术栈清单（语言、框架、数据库、中间件）
- 目录结构树 + 各目录职责标注
- 启动/构建方式
- 部署架构简述

## 架构设计

**目标**：理解项目的整体设计思路、分层方式、核心设计决策。

**分析方法**：
1. 从入口文件出发，追踪请求处理链路
2. 识别分层模式（MVC / DDD / 六边形 / 微服务等）
3. 分析中间件/拦截器注册顺序
4. 识别核心设计模式的应用（工厂、策略、观察者等）
5. 分析模块间的依赖方向

**产出笔记**：`架构设计.md`

**必须包含**：
- 架构风格/分层方式描述
- 请求处理链路（从入口到响应的完整路径），配代码片段
- 核心中间件/拦截器及其注册代码
- 关键设计模式及其应用场景
- 模块依赖关系（文字描述或 ASCII 图）

**代码片段示例**：
```markdown
请求从入口进入后的处理链路：

` ``python
# src/app.py:10-25 - 应用入口和中间件注册
app = Flask(__name__)
app.register_blueprint(auth_bp, url_prefix='/auth')
app.register_blueprint(api_bp, url_prefix='/api')

@app.before_request
def authenticate():
    # 所有 /api 开头的请求都需要认证
    if request.path.startswith('/api'):
        verify_token(request.headers.get('Authorization'))
`` `
```

## 模块解读

**目标**：深入理解每个核心模块的内部实现。

**分析方法**：
1. 识别模块边界（通常是一个目录或一组紧密相关的文件）
2. 确定模块的对外接口（被其他模块调用的函数/类）
3. 分析模块内部的类/函数结构
4. 对核心/复杂函数进行逐行解读
5. 标注模块的上游调用者和下游依赖

**每个模块一篇笔记**，文件名格式：`模块名-核心功能`

**解读深度分级**：
- **核心函数**（业务逻辑的主干）→ 完整解读：函数签名、参数说明、实现逻辑、返回值、错误处理、代码片段
- **辅助函数**（工具类、格式化、校验）→ 简要说明：一句话职责 + 关键参数
- **样板代码**（getter/setter、标准 CRUD）→ 一笔带过或不提

**核心函数解读模板**：
```markdown
### `function_name(param1, param2) -> ReturnType`

**职责**：一句话说明

**调用场景**：在 XXX 流程中被 YYY 调用

` ``python
# src/module/core.py:45-78
def function_name(param1: str, param2: int) -> Result:
    """核心处理逻辑"""
    # 1. 参数校验
    if not param1:
        raise ValueError("param1 不能为空")

    # 2. 核心业务逻辑
    result = complex_calculation(param1, param2)

    # 3. 结果封装
    return Result(data=result, status="success")
`` `

**关键点**：
- 校验逻辑在第 48 行，失败时抛出 ValueError 而非返回 None
- `complex_calculation` 来自 [[模块/计算引擎]]，是 CPU 密集型操作
- 返回的 Result 对象定义在 [[数据模型/通用响应模型]]
```

## 核心流程

**目标**：串联多个模块，展示关键业务流程的完整调用链。

**分析方法**：
1. 识别项目中的核心用户场景（登录、下单、支付等）
2. 从入口（Controller/Handler）开始，逐层追踪调用链
3. 记录每个环节调用的模块和函数
4. 标注关键分支（成功/失败/异常路径）

**产出笔记**：每个核心流程一篇

**必须包含**：
- 流程触发条件和入口
- 调用链（按顺序列出每个环节）
- 每个环节的关键代码片段
- 异常处理路径
- 涉及的模块链接（Wikilink）

**调用链格式示例**：
```markdown
## 用户登录流程

1. **入口** — `POST /auth/login` → [[API接口/认证接口]]
2. **参数校验** — `validate_login_request()` → [[模块/请求校验]]
3. **用户查找** — `user_repo.find_by_email()` → [[模块/用户管理]]
4. **密码验证** — `verify_password()` → [[模块/认证模块-密码处理]]
5. **Token 生成** — `create_access_token()` → [[模块/认证模块-JWT鉴权]]
6. **响应返回** — 返回 `{token, user_info}`

### 异常路径
- 步骤 3 用户不存在 → 返回 401
- 步骤 4 密码错误 → 返回 401，记录失败次数
- 步骤 4 账户被锁定 → 返回 403
```

## 数据模型

**目标**：理解数据结构设计和实体间关系。

**分析方法**：
1. 读取 ORM 模型定义文件（models.py / entities/ / schema.prisma 等）
2. 读取数据库迁移文件（如果有）
3. 分析实体间关系（一对一、一对多、多对多）
4. 识别核心字段和索引

**产出笔记**：可以按领域分多篇，或合为一篇

**必须包含**：
- 实体清单及其核心字段
- 实体间关系描述
- 关键索引和约束
- ORM 模型定义代码片段

## API 接口

**目标**：梳理项目的对外接口。

**分析方法**：
1. 扫描路由定义文件
2. 提取每个接口的：路径、方法、参数、响应格式
3. 如果有 OpenAPI/Swagger 定义，直接读取

**产出笔记**：按功能域分组

**必须包含**：
- 接口清单表格（路径、方法、简述）
- 关键接口的请求/响应示例
- 认证要求
- 错误码说明

---

## 配置体系

**目标**：理解项目如何管理配置。

**分析方法**：
1. 读取 `.env.example` 或配置文件
2. 分析配置的加载方式和优先级
3. 识别环境区分（dev/staging/prod）

**产出笔记**：`配置体系.md`

## 依赖关系

**目标**：理解项目的外部依赖选型和内部模块依赖。

**分析方法**：
1. 从包管理文件提取外部依赖
2. 分析核心依赖的用途
3. 从 import 关系分析内部模块依赖方向

**产出笔记**：`依赖关系.md`

**必须包含**：
- 核心外部依赖表格（名称、版本、用途）
- 内部模块依赖方向描述
