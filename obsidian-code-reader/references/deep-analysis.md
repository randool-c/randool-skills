## 子模块识别启发式

目标：将一个模块目录下的文件划分为若干内聚的子模块，每个子模块产出一篇笔记。

**优先级从高到低：**

### 1. 子目录即子模块

如果模块源码目录有子目录结构，每个子目录天然是一个子模块：

```
src/auth/
├── jwt/          ← 子模块: JWT鉴权
│   ├── verify.py
│   └── create.py
├── password/     ← 子模块: 密码处理
│   ├── hash.py
│   └── validate.py
└── middleware.py  ← 归入父模块总览或独立子模块
```

### 2. 文件名公共前缀分组

无子目录时，按文件名前缀聚合：

```
src/auth/
├── jwt_verify.py      ← 子模块: JWT鉴权
├── jwt_create.py      ←
├── password_hash.py   ← 子模块: 密码处理
├── password_validate.py ←
└── rbac.py            ← 子模块: 权限控制
```

前缀提取规则：取第一个 `_` 或驼峰分词的首段。相同前缀的文件归为一组。

### 3. Import 内聚性分析

读取文件的 import/require 语句，构建依赖矩阵：
- 互相 import 频繁（≥2 次）但对外 import 少的文件 → 内聚子模块
- 适用于文件名无规律的情况

### 4. 语义分组（兜底）

以上规则无法有效分组时，由 Claude 根据函数语义手动分组：
- 读取每个文件的公开函数/类列表
- 按业务职责归类（如：鉴权相关、数据处理相关、工具函数）
- 向用户展示分组方案确认

**分组结果约束：**
- 每个子模块包含 2-8 个文件为宜
- 单文件模块（只有 1 个源文件）直接合入总览，不单独建笔记
- 超过 8 个文件的子模块考虑进一步拆分

## 目录结构迁移算法

将单一扁平模块笔记转换为带子目录的深度结构。

### 迁移前

```
模块/
├── _index.md
├── 10-认证模块-权限校验.md    ← 单一扁平笔记
├── 20-用户管理-CRUD.md
└── 30-数据处理-ETL.md
```

### 迁移后

```
30-模块/
├── _index.md               ← 更新：认证模块条目从笔记表移至子目录表
├── 10-认证模块/            ← 新建目录
│   ├── _index.md           ← 原笔记内容迁移 + 子模块导航表
│   ├── 10-JWT鉴权.md
│   ├── 20-密码处理.md
│   └── 30-权限控制.md
├── 20-用户管理-CRUD.md     ← 不变
└── 30-数据处理-ETL.md      ← 不变
```

### 迁移步骤

**步骤 1：提取模块名**

从原笔记文件名提取模块名，去掉 `NN-` 前缀后取第一个 `-` 之前的部分：
- `10-认证模块-权限校验` → `认证模块`
- `30-数据处理-ETL` → `数据处理`

如果用户指定了模块名，直接使用。

**步骤 2：创建模块目录**

```bash
mkdir -p "NN-模块/NN-<模块名>"
```

其中 `NN` 沿用原扁平笔记的序号前缀。

**步骤 3：迁移原笔记为总览**

将原笔记内容写入 `NN-模块/NN-<模块名>/_index.md`，并进行改造：
1. 保留原 frontmatter（更新时间戳）
2. 保留原有的「定位与职责」「关键设计决策」「依赖关系」等高层内容
3. 在「核心实现」部分替换为子模块导航表：

```markdown
## 子模块导航

| 子模块 | 职责 | 源文件 |
|--------|------|--------|
| [[10-JWT鉴权]] | JWT token 的生成与验证 | jwt.py, token_utils.py |
| [[20-密码处理]] | 密码哈希与校验 | password.py, hash_utils.py |
| [[30-权限控制]] | RBAC 权限管理 | permissions.py, decorators.py |
```

4. 原笔记中的详细代码片段迁移到对应子模块笔记中

**步骤 4：删除原扁平笔记**

确认迁移完成后，删除 `NN-模块/NN-<原笔记名>.md`。

**步骤 5：无原笔记时的处理（独立运行）**

如果该模块没有已有笔记（独立运行模式），直接生成总览 `_index.md`：
- 从源码扫描结果生成模块定位描述
- 生成子模块导航表
- 分析依赖关系

```markdown
# 子模块标题

## 定位与职责

> 一句话说明该子模块在父模块中的角色。

在 [[NN-模块/NN-<父模块>/_index|NN-<父模块>]] 中负责 XXX。

## 函数清单

| 函数 | 文件 | 职责 | 复杂度 |
|------|------|------|--------|
| `verify_token()` | jwt.py:15 | 验证 JWT token | 中 |
| `create_token()` | jwt.py:45 | 生成 JWT token | 低 |
| `refresh_token()` | jwt.py:78 | 刷新过期 token | 中 |

复杂度说明：低（直接调用库/简单逻辑）、中（有分支/错误处理）、高（复杂算法/多层嵌套）

## 核心实现

### `verify_token(token: str) -> dict`

**职责**：验证 JWT token 并返回 payload

**调用场景**：在 [[NN-模块/NN-<父模块>/NN-权限控制]] 的中间件中被调用

` ``python
# src/auth/jwt.py:15-32
def verify_token(token: str) -> dict:
    """验证 JWT token"""
    try:
        payload = jwt.decode(token, SECRET_KEY, algorithms=["HS256"])
        return payload
    except jwt.ExpiredSignatureError:
        raise AuthError("Token 已过期")
`` `

**关键点**：
- 选择 HS256 而非 RS256，因为是单体应用无需非对称加密
- 过期异常显式抛出自定义 AuthError，由上层统一处理

### `create_token(user_id: int, role: str) -> str`

（同样格式...）

## 内部调用关系

子模块内函数间的调用链：
1. 外部请求 → `verify_token()` → 解码 + 校验过期
2. 登录成功 → `create_token()` → 编码 payload
3. token 过期 → `refresh_token()` → 调用 `verify_token()` 验证旧 token → 调用 `create_token()` 生成新 token

## 依赖关系

- 上游：被 [[NN-模块/NN-<父模块>/NN-权限控制]] 的认证中间件调用
- 下游：依赖 PyJWT 库、项目配置中的 SECRET_KEY
- 同级：与 [[NN-模块/NN-<父模块>/NN-密码处理]] 无直接依赖

## 相关笔记

- [[NN-模块/NN-<父模块>/_index|NN-<父模块>总览]]：模块整体架构
- [[40-核心流程/10-用户认证流程]]：完整认证链路
- [[70-配置体系]]：SECRET_KEY 配置来源
```

## _repo_meta.md 映射演化

深剖后，粗粒度映射需要展开为精细映射。

### 演化前

```markdown
| 源文件/目录 | 对应笔记 | 解读范围 |
|------------|---------|---------|
| src/auth/ | [[30-模块/10-认证模块-权限校验]] | 整个目录 |
| src/auth/jwt.py | [[30-模块/10-认证模块-权限校验]] | 文件级 |
```

### 演化后

```markdown
| 源文件/目录 | 对应笔记 | 解读范围 |
|------------|---------|---------|
| src/auth/ | [[30-模块/10-认证模块/_index]] | 深剖总览 |
| src/auth/jwt.py | [[30-模块/10-认证模块/10-JWT鉴权]] | 文件级 |
| src/auth/token_utils.py | [[30-模块/10-认证模块/10-JWT鉴权]] | 文件级 |
| src/auth/password.py | [[30-模块/10-认证模块/20-密码处理]] | 文件级 |
| src/auth/hash_utils.py | [[30-模块/10-认证模块/20-密码处理]] | 文件级 |
| src/auth/permissions.py | [[30-模块/10-认证模块/30-权限控制]] | 文件级 |
| src/auth/decorators.py | [[30-模块/10-认证模块/30-权限控制]] | 文件级 |
```

### 演化规则

1. **删除**所有指向原扁平笔记的映射行（匹配 `[[NN-模块/NN-<原笔记名>]]`）
2. **新增总览行**：`src/<模块目录>/ → [[NN-模块/NN-<模块名>/_index]] | 深剖总览`
3. **新增精细行**：每个源文件映射到对应子模块笔记（带 `NN-` 前缀），`解读范围` 标注为 `文件级`
4. `解读范围` 列新增值 `深剖总览`，标识该行是深剖后的模块总览入口
5. 更新「解读覆盖统计」的已解读文件数

### 同步兼容

`仓库同步`（Command 3）处理深剖后的模块时：
- 检测到变更文件映射到子模块笔记 → 更新对应子模块笔记
- 检测到模块目录下新增文件但不在任何子模块映射中 → 提示用户可对新文件补充深剖
- `深剖总览` 行不直接触发更新，而是在子模块更新后同步更新总览中的导航表

## Wikilink 迁移规则

深剖时笔记路径发生变化，需要更新所有引用。

### 路径变化

| 原路径 | 新路径 |
|--------|--------|
| `30-模块/10-认证模块-权限校验` | `30-模块/10-认证模块/_index` |

### 迁移步骤

**步骤 1：扫描所有引用**

在仓库解读目录下搜索所有包含原路径 Wikilink 的文件：

```bash
grep -rl '\[\[30-模块/10-认证模块-权限校验' <vault>/代码解读/<仓库名>/
```

**步骤 2：批量替换**

对每个匹配文件，执行替换：
- `[[30-模块/10-认证模块-权限校验]]` → `[[30-模块/10-认证模块/_index|10-认证模块]]`
- `[[30-模块/10-认证模块-权限校验|显示文本]]` → `[[30-模块/10-认证模块/_index|显示文本]]`（保留原显示文本）

**步骤 3：上下文精准替换（可选）**

如果原引用上下文明确指向某个具体子主题（如"JWT 验证逻辑详见 [[30-模块/10-认证模块-权限校验]]"），可将链接替换为具体子模块：
- `[[30-模块/10-认证模块-权限校验]]` → `[[30-模块/10-认证模块/10-JWT鉴权]]`

此步骤由 Claude 根据上下文语义判断，非机械替换。

**步骤 4：验证**

替换完成后，扫描确认不再有指向原路径的 Wikilink：
```bash
grep -r '\[\[30-模块/10-认证模块-权限校验' <vault>/代码解读/<仓库名>/
```

应返回空结果。
